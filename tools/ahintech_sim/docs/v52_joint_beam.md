# V52 — complete-target-set beam up to 12 devices

V51 remains the last **officially scored** submission (~85.1736 points). V52 is a standalone C++23 experimental candidate; no official hidden-judge result is yet available.

## Core mathematical change

For each activation hour, a candidate is a **subset of recipients**, not an independent choice of one recipient. Every subset must be assignable to currently activated sender devices with quota `k` and no duplicate target; the simulator's subsequent states track all unpacking intervals. Beam search retains different valid state histories over the whole finite horizon.

V51's subset beam was capped at `n <= 10`, partly because of hard-coded arrays and the exponential per-sender subset enumeration. V52 extends this to `n <= 12`, still within 64 bits (five bits of unfinished unpacking duration per device), with a new safe fast path:

1. Let `U` be the set of all eligible recipients adjacent to any currently active sender.
2. Test whether the **entire set U** can be assigned to those senders respecting each quota `k`, by capacitated bipartite matching.
3. If yes, *every subset of U is feasible*, because any matching can be restricted to that subset. Enumerate these subsets directly, rather than repeatedly building all partial matchings.
4. Otherwise, fall back to the exact subset feasibility DP already present in V51. Both paths use the same limited-width beam and preserve witness recovery.

This feasibility shortcut does not change the mathematical answer: it is an implication of the downward-closed set of feasible capacitated assignments. The beam remains a **heuristic** due to limited width, but every generated activation schedule is checked independently.

## MILP-certified development examples

These are deterministic synthetic problems generated by `counterexample_miner.py` with `--seed 20261213`, indices `0`, `1`, `5` (per-index seed `20261213 + 9199*i`). `milp_oracle.py` / SciPy-HiGHS certified the optimum on all three. Stored SHA-256 hashes prevent accidental input changes.

| Case | V51 | V52 | Proven optimum |
|---|---:|---:|---:|
| n=12, m=60, k=4 | 137 | **144** | 144 |
| n=12, m=72, k=4 | 313 | **314** | 314 |
| n=12, m=72, k=6 | 286 | **292** | 292 |

First example: full beam finished in ~0.22 s; entire executable ~1.86 s locally. On a 12-case newly mined set V52 improved 3 cases, and retained V51's counts on the rest; those outcomes do not predict official points.

The `tests/test_v52_joint_beam.py` test runs the C++ binary under the normal 2-second clock with a small process timeout, validates outputs and expected optima; when SciPy is installed it also recomputes the MILP certificates. Run the independently seeded counterexample miner to find the next gaps, especially `n=13..14` not handled by the new beam.

**Caveat:** the older V51 modes and exact-small solver are unchanged; n>12 uses the existing V51 algorithms. The new subset beam may consume additional up-front time on n=11..12. This is intentionally guarded by `0.72 s` and the solver's wall-clock reserve. Never infer an official score improvement from the development fixtures alone.
